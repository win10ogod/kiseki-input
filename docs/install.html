KISEKI INPUT · GET STARTED

安裝後，從一個終端機開始。

Kiseki 是讓 agent 操作桌面應用程式的原生 CLI。原生鍵鼠、截圖和視窗操作可直接使用；需要 CUA 時，Kiseki 會在開始流程時安裝或更新官方 Cua Driver。

1. 選對安裝包

從 GitHub Releases 的 Assets 下載。一般使用者選安裝程式；要自行選擇位置則選 ZIP / TAR.GZ。

你的系統建議檔案
Windows 10 / 11，64 位元Windows 的 .exe 安裝程式
macOS 14+，Apple SiliconDarwin-arm64 的 .pkg
macOS 14+，IntelDarwin-x86_64 的 .pkg
Ubuntu 22.04+ / 相容 Debian 系統Linux-x86_64 或 Linux-aarch64 的 .deb

Windows：執行安裝程式，選擇加入 PATH，完成後開啟新的 PowerShell。開始選單中的「Start here」可再次開啟本指南。macOS：開啟 PKG，依安裝精靈完成後開啟 Terminal。Linux：在下載目錄執行 sudo apt install ./KisekiInput-….deb，由 apt 安裝相依套件。

若系統提示發行者尚未驗證，先核對下載來源及附帶的 SHA-256。簽署狀態取決於該版本是否配置發行憑證；詳細處理方式見完整指南。

2. 確認 Kiseki 已可執行

kiseki --version
kiseki modes --json
kiseki capabilities

這三個命令只檢查版本與功能，不會移動滑鼠或開始錄製。若出現找不到命令，重開終端機，或先使用安裝目錄中的 bin/kiseki（Windows 是 bin\kiseki.exe）。

3. 開始 CUA 操作流程

kiseki background cua setup
kiseki background cua status
kiseki background cua windows

第一次 setup 會下載官方 Driver。之後每次開始流程，都會檢查所選通道的新版本並自動更新。windows 與 launch 也會執行此準備流程。鍵鼠 action 不會在中途觸發更新。

macOS：請在有登入桌面的 Terminal 執行。依系統提示為 CuaDriver 開啟「輔助使用」及「螢幕錄製」。若沒有跳出提示，執行 kiseki background cua status --prompt，再到「系統設定 → 隱私權與安全性」確認。回到終端機重新執行 setup / status 即可。

Windows / Linux：請在要操作的使用者桌面中執行。Linux 原生 X11 與 Wayland 的可用功能依 compositor、桌面 session 和 provider 回報而定；status 顯示實際準備狀態。

網路暫時不可用時，已安裝的 Driver 仍可使用，更新失敗原因會保留在輸出中。指定的 Driver 路徑、版本 pin 或自訂 daemon 端點不會被自動替換。

4. 交給 agent 使用

安裝目錄的 share/kiseki/skills 內附兩份 skill：kiseki-project 負責觀察、定位、操作、驗證；kiseki-teach-recording 負責教學錄製、檢查與 skill 生成。讓 agent 讀取對應的 SKILL.md，或依 agent 平台的方式安裝整個 skill 資料夾。

CLI 本身不需要 Python；skill 的檢查、錄製控制及草稿工具需要 Python 3.9+。先讀取視窗狀態，再依本次截圖及 snapshot 選擇目標，最後確認應用程式真的完成操作。

kiseki background cua tools
kiseki background cua describe get_window_state
kiseki background cua call get_window_state --file request.json

完整 JSON 呼叫保留 provider 的參數與結果，可直接使用該版本新增的工具。
