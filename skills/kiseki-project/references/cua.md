# CUA operation

Begin a new CUA workflow with `background cua setup`. It installs a missing native Driver, checks for an update at most once per 24 hours (the Driver's own cache; `background cua update` checks now) and applies it, and starts the daemon. `windows` and `launch` also prepare a workflow; `status` only checks readiness. Do not insert setup/discovery between a snapshot and its element action. Read [CUA integration](../../../docs/cua.md) for update controls, installer side effects, Driver 0.49 changes and service ownership.

1. Set `KISEKI_CUA_SESSION` to a task-specific name for concurrent or repeated work. Convenience state/action/feedback commands use that name (default `kiseki`).
2. Start it with `background cua session start` (or `call start_session` with that `session`). A session ends after five idle minutes or `session end`; Kiseki starts a session you named again once when the provider says it ended.
3. Discover PID/window IDs in the current host/session (`windows --pid`/`--app`); reuse the task's established app. `launch --name` is portable; macOS bundle IDs, Windows `--aumid`/`--path` and launch paths come from the installed provider's `launch_app` schema.
4. Read `state --pid ... --window-id ... --output ...`. Retain the `snapshot_id`, the `[N]` row or element token, and the screenshot's pixel frame. Without `--output`, state takes no screenshot. A truncated tree or a reduced screenshot is noted on stderr; use `--max-elements`, `--query`, `--timeout-ms`, `--full-output` or `--max-image-dimension 0` as the task needs.
5. Address elements with `--element-token SNAPSHOT:N`, or `--element-index N --snapshot-id SNAPSHOT` (sent as that token) for click/text/key/hotkey. An index without its snapshot is rejected. Re-observe when the app changes (`state --since latest` returns only changes). Do not replace a stale token with an unverified index.
6. x/y use the pixels of the window's latest capture: effective ratio `screenshot_width / window_bounds.width`, not `screenshot_scale`. Make `state --output` or `screenshot` the latest read before x/y actions; after a structural read the provider refuses them (`screenshot_context_missing`). After `text --element-token`, read the whole value back.
7. Confirm the app effect with fresh structured state or a screenshot. Keep current-session native input separate from selected-window CUA requests.
8. End the task's named session when complete. Stop a daemon only if the task owns it and no further use is requested.

Use `background cua tools` and `describe TOOL` to learn the installed provider. `call TOOL --file request.json` preserves all JSON fields, including new tools and platform-specific options. This is the route for scroll, window geometry, `run_steps`, or any capability not covered by convenience flags. `--delivery-mode` is an explicit user choice; never change delivery mode or reduce precision fields to turn an error into success.

Screenshots use `get_window_state` without the tree walk; `--pid` skips the window lookup. JPEG (`.jpg` output or `--format jpeg`) works where the Driver offers `screenshot_format` (macOS 0.49.9); elsewhere Kiseki reports it unavailable and writes nothing. `draw` sends each segment as its own drag, batched through `run_steps`; it is not one held stroke. Cursor colors are installed themes (`cursor-theme -- list`, `theme`); `feedback style` and the colors of `feedback preset` need a Driver older than 0.25.

When setup reports a warning, keep it in the result. An offline check leaves the installed version usable; first-time installation failure needs its exact installer error. Kiseki-started installs and updates skip `cua-driver connect`, `cua-driver test`, shell PATH edits on update and (Windows) the elevated logon task. macOS permissions belong to CuaDriver.app; Windows/Linux need the target graphical session. A custom `KISEKI_CUA_DRIVER`, version pin or `KISEKI_CUA_SOCKET` stays under its owner's control.
